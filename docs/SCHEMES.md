# Muse: схемы логики, взаимодействия и аудит

Документ описывает внутреннюю логику приложения, схемы взаимодействия с API Яндекса,
найденные в ходе аудита недоработки и их статус, а также чек-лист типовых жалоб
пользователей музыкальных плееров и как с ними обстоит дело в Muse.

---

## 1. Общая архитектура (поток запуска)

```
Старт
 ├─ tokenManager.load() ── токен есть?
 │    ├─ НЕТ  → welcome-экран → логин (OAuth-редирект) → токен в localStorage
 │    └─ ЕСТЬ → boot(): account/status → refreshUser, refreshLikes, refreshPlaylists
 │              (параллельно; каждая секция независима, ошибки — тост, не блок)
 ├─ Splash (~1.6 с) → главный экран (HashRouter)
 ├─ Навигация: сайдбар (десктоп) / нижняя панель (телефон ≤768px):
 │   Главная · Поиск · Радио · Избранное · История · Настройки
 └─ Компоненты-оверлеи: развёрнутый плеер (psheet), очередь, текст песни,
     похожие треки, подтверждение удаления, тосты
```

## 2. Плеер (player.ts) — схема состояний

```
playQueue(items, idx, radio?)
    │
    ├─ очередь = items, index = idx
    ├─ loadAndPlay(item)
    │    ├─ resolveStreamUrl(track)  → /tracks/{id}/download-info → выбор codec
    │    │    (mp3 320→192→128→aac→hls→flac; cap по настройке качества)
    │    │    без directLink → XML downloadInfoUrl → md5-подпись → https://{host}/get-mp3/…
    │    ├─ audio.src = url → play()
    │    ├─ Media Session: title/artist/artwork + клавиши prev/next/play/pause/seek/stop
    │    └─ фон: на Android WebView/Electron — кастомный backgroundPlayback (уведомление)
    │
    ├─ next()/prev() → step(±1)
    │    ├─ radio: ensureRadioBuffer (добрать ~2 трека), feedback trackStarted/Finished
    │    └─ shuffle: случайный индекс; repeat: 'all' кольцо / 'one' рестарт
    │
    └─ ended/error → failTrack → onEnded(skipError) → step(+1) (пропуск битых треков)
         конец очереди → backgroundPlayback.stop()

Очередь: QueuePanel — прыжок по клику, удаление строки (removeIndex),
        текущий удаляется → играет следующий; счётчик в шапке.
Свайпы в развёрнутом плеере (по обложке, pointer-события):
        влево → next(), вправо → prev(), вниз → свернуть; порог |dx|>60 и |dx|>1.4|dy|.
```

## 3. Избранное и плейлисты — схема операций

```
«Избранное» (/likes)
 ├─ Секция «Мои плейлисты»:
 │    ├─ плейлистов нет  → CTA «Создать первый плейлист» → инлайн-ввод → createPlaylist
 │    │                     → refreshPlaylists → лента карточек
 │    └─ есть → горизонтальная лента .fav-row (карточки 150px, скролл без полосы)
 ├─ Секция «Избранные треки · N»: лайки (GET /likes/tracks → expandTracks),
 │    спиннер до ответа, «▶ Играть всё»
 └─ Меню трека «⋮» (везде, где TrackList):
      [в контексте плейлиста] «Убрать из плейлиста» (delete [i, i+1))
      «Добавить в плейлист» → список плейлистов (имя + счётчик) → insert at end
      «Создать плейлист» → переход на /playlists

Плейлист (PlaylistPage)
 ├─ GET /users/{uid}/playlists/{kind}?withTracks=true
 │    нормализация записей: {id, track: Track} ИЛИ плоские {id, albumId}
 │    (раньше вложенный track не распознавался → «треки не пригружались»)
 ├─ «▶ Играть» (очередь с source=playlist)
 ├─ «Удалить плейлист» → модальное подтверждение → POST .../delete → /playlists
 └─ Меню строки: убрать трек → playlistDeleteRange(pl, i, i+1)

КРИТИЧНО — ревизии Yandex API:
 ├─ каждая успешная операция change увеличивает revision плейлиста
 ├─ запрос change БЕЗ актуальной revision → «Expected revision: N, actual revision: M»
 ├─ решение: всегда перечитываем плейлист перед insert/delete (свежие revision + trackCount)
 └─ при ошибке /revision/i — повтор с перечитанной ревизией (защита от параллельных устройств)

Семантика операций change (проверено эмпирически):
 ├─ insert: { op: 'insert', at: N, tracks: [{id, albumId}] }  — 0-based, вставка перед N
 └─ delete: { op: 'delete', from: i, to: i+1 } — ИНТЕРВАЛ [from, to): to НЕ включается
      (в коде была ошибка: передавали (i, i) → API молча НЕ удалял — исправлено)
```

## 5. Типовые жалобы пользователей плееров (по базе знаний) и статус в Muse

| Жалоба пользователя | Как решено в Muse |
|---------------------|-------------------|
| «Хочу свайпами листать треки» | ✅ свайпы влево/вправо в развёрнутом плеере |
| «Не могу удалить трек из плейлиста» | ✅ меню «⋮» → «Убрать из плейлиста» |
| «Не могу удалить плейлист» | ✅ «Удалить плейлист» с подтверждением |
| «Раздел лайков неудобный, плейлисты непонятно где» | ✅ «Избранное»: плейлисты лентой сверху, треки ниже |
| «Добавление в плейлист — долго/непонятно» | ✅ меню трека: список плейлистов с количеством, тост об успехе |
| «Хочу видеть очередь и убирать из неё» | ✅ QueuePanel: клик-прыжок, ✕ удалить строку |
| «Случайно меняются треки, нет подсказок» | ✅ подсказка «← свайп →» на обложке, tooltip'ы кнопок |
| «Пустые экраны пугают до загрузки» | ✅ спиннеры вместо «пусто» |
| «Ошибки API непонятны» | ✅ тосты с понятным текстом на русском |
| «Хочу фоновое воспроизведение» | ✅ Media Session (браузер/десктоп) + WebView-бэкграунд (Android) |
| «Не хватает быстрых действий» | ✅ shuffle/repeat/перемотка/громкость в развёрнутом плеере |

*Ограничение: внешний веб-поиск отзывов недоступен (квота API исчерпана) —

## 7. Нативный медиа-виджет Android (как у Яндекс Музыки)

```
JS (mediaControl.ts) ──update(state)──▶ BackgroundPlayback (плагин)
   ▲                                        │
   │                                        ▼
   │                              PlaybackService (foreground, MediaSession)
   │                                ├─ Notification.MediaStyle:
   │                                │    обложка, название, исполнитель,
   │                                │    [◀] [⏯] [▶] [★ лайк], seekbar
   │                                ├─ MediaSession: play/pause/next/prev/seek
   │                                └─ системные медиа-управления (шторка, локскрин, часы)
   │                                        │
   └────── playbackAction ◀─────────────────┘
        {action: play|pause|next|prev|seek|like, positionMs}
```

- Состояние пушится из JS при смене трека/паузы/позиции/лайка (троттлинг ~0.5 с).
- Кнопки уведомления и seekbar → PendingIntent/MediaSession → `BackgroundPlayback.dispatch` → JS.
- Лайк: кнопка в уведомлении + custom action MediaSession (виден в системных медиа-контролах).
- Обложка грузится фоном (Bitmap, кеш по URL), largeIcon 84×84.
- Тап по уведомлению открывает приложение (MainActivity, singleTask).

## 8. Свайп-управление (все страницы)

| Где | Жест | Действие |
|-----|------|----------|
| Любая страница | свайп от левого края вправо | «Назад» (history.back), кроме корневых вкладок |
| Строка трека | свайп влево | открыть меню действий (⋮) |
| Строка трека | свайп вправо | лайк/анлайк |
| Развёрнутый плеер (обложка) | влево/вправо | следующий/предыдущий трек |
| Развёрнутый плеер (обложка) | вниз | свернуть плеер |

Пороги: edge-back — старт в первых 34 px, |dx|>90, |dx|>1.5|dy|, <700 мс;
строка — |dx|>60, |dx|>1.5|dy|; плеер — |dx|>60, вниз dy>110.
После свайпа клик «играть» подавляется (400 мс), чтобы не запускать трек случайно.

## 9. Непрерывность воспроизведения

- **Очередь кончилась** (не радио, не repeat-all) → `extendWithSimilar()`:
  `GET /tracks/{id}/similar` → `POST /tracks` (полные треки) → дописываем до 20 похожих
  в конец очереди и играем дальше. Так «Моя волна» продолжается из поиска/избранного.
- **Защита от каскада**: 3 подряд ошибки воспроизведения → стоп с понятным сообщением
  (раньше в фоне play() мог отклоняться и плеер бесконечно скипал всю очередь).
- **Сохранение очереди**: `ym.queue` в localStorage (ids, sources, index, positionMs, radio),
  persist форсируется на playQueue/step/enqueue/removeIndex/расширении; при старте
  `player.restore()` подтягивает треки и ставит текущий на позицию (пауза).

# OAuth Яндекс: жизненный цикл токена и проблема «токен кончился»

## Как устроен токен

1. Приложение получает `access_token` через OAuth Device Flow (подробности — в `docs/api-notes.md`).
2. `access_token` — короткоживущий. `expires_in` из ответа OAuth говорит, через сколько секунд он перестанет работать (часто 30 суток для Device Flow этого client_id, но **не гарантировано**).
3. В ответ может прийти `refresh_token` — им `access_token` можно обновлять без повторного входа. **Опционально**: Яндекс может не выдать его.
4. Сервер может отозвать токен в любой момент (смена пароля, «выйти из всех приложений», пометка устройства). Тогда все запросы начнут падать с HTTP 401 `Unauthorized`.

## Как это решено в YM Player (три рубежа)

```
[1] Автообновление по refresh_token
    access_token истёк / скоро истечёт / сервер вернул 401
    → POST oauth.yandex.ru/token (grant_type=refresh_token)
    → сохранили новый токен, повторяем запрос
                    ↓ (refresh не сработал / его не было)
[2] Прозрачный повторный вход (Device Flow)
    экран входа как при первом запуске, после входа — продолжаем с того места
                    ↓ (аккаунт недоступен)
[3] Честная ошибка
    «Токен Яндекса истёк или отозван — войдите заново» (тост + экран входа)
```

Реализация: `src/core/tokenManager.ts`.

### Тонкости

- **401 vs 403**: 401 → повторная авторизация/refresh; 403 → скорее всего региональные ограничения или нет подписки на трек, не трогаем токен.
- **Гонки**: несколько параллельных запросов не должны одновременно делать refresh — в `tokenManager` один общий `Promise` (мьютекс).
- **Порог**: токен считается «умирающим» за 5 минут до `expiresAt`; настройки показывают дату истечения и кнопку принудительного обновления.
- **Ручной токен без срока** (`expiresIn: 0`) не пытаемся обновлять — считаем валидным.
- **Хранение**:
  - Веб: `localStorage` (просто, но XSS-чувствительно — приемлемо для локального плеера).
  - Electron: перевести на `safeStorage` (шифрование ОС) — TODO в чек-листе, API готов.
  - Android (Capacitor): `@capacitor/preferences` — TODO.
- Никогда не сохраняем токен в git/логи.

## Код устройства (Device Flow)

| Шаг | Запрос | Ответ |
|---|---|---|
| 1 | `POST /device/code` (client_id, device_id, device_name) | `device_code`, `user_code`, `verification_url`, `expires_in`, `interval` |
| 2 | Показываем `user_code` и ссылку, пользователь вводит код на ya.ru/device | — |
| 3 | Цикл `POST /token` (grant_type=device_code, code, client_secret) | `access_token` / `authorization_pending` / `access_denied` / `expired_token` |

Код уже проверен живыми запросами: `/device/code` отвечает корректно через прокси, опрос возвращает `authorization_pending` (пока пользователь не подтвердил).

## Проверка для разработчика

Полный цикл «вход → лайки → плейлисты → воспроизведение» проверяется только с реальным аккаунтом:
1. Открыть `http://localhost:5173`, нажать «Войти через Яндекс».
2. На экране появится код вида `wwqvpp75` и ссылка — подтвердить вход.
3. Токен сохранится, плеер сам загрузит профиль, лайки, плейлисты.

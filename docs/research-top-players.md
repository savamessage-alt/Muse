## Лучший по отзывам

Критерий: звёзды (доверие сообщества) + активность (последний push, исправления) +
характер issues (сколько реальных жалоб, решаются ли).

**Лидеры:**

1. **spotube (team-spotube/spotube)** — абсолютный эталон рынка: ~50 600⭐, активный
   push (2026-11-03), кросс-платформа desktop+mobile, community-сборки. Это
   «золотой стандарт» UX стриминг-плеера, на который ориентируются все остальные.
   Минус для нас: это не React, а Kotlin/Compose (после rewrimag-переписи) — брать
   можно только *приёмы интерфейса*, не код.
2. **nuclear (nukeop/nuclear)** — ~18 900⭐, TS/React/Electron + Vite + Tailwind,
   активный (push день в день). **Лучший эталон для нашей стеки (React+TS+Vite)**:
   система иконок (lucide), раскрывающийся нижний плеер, очередь, слайдеры подкастов
   и радио.
3. **muffon (staniel359/muffon)** — ~2 300⭐, активный (2026-10-26), единственный
   крупный клиент **с прямой интеграцией Яндекс Музыки** среди открытых
   «из коробки». Наиболее релевантный источник жалоб и UI-решений именно для
   нашего бэкенда. Стек Vue (не React), потому берём идеи, не код.

**Вывод для проекта (Яндекс Музыка, моб/десктоп):**
- **по UX-эталону** — копируем паттерны spotube/nuclear (нижний мини-плеер,
  bottom-sheet, очередь, тексты, пустые состояния);
- **по Yandex-специфике** — берём опыт muffon (авторизация источника, ошибки
  воспроизведения, экспорт) и Маршаловской `yandex-music-api` для бэкенда.

## Жалобы пользователей (из issues, сгруппировано)

Собрано из открытых issues **muffon** (вкладка issues, сортировка по комментариям) —
это единственный крупный открытый клиент с жалобами именно про мульти-источниковый
плеер с Яндекс Музыкой. У **nuclear** открытые issues почти полностью забиты
ботами (dependabot/renovate: «Update lucide monorepo», «Lock file maintenance»,
«Dependency Dashboard»), т.е. реальных user-complaints на верхушке мало — сам по
себе факт «мало людских issues» говорит о стабильности. У spotube огромный
бэклог (419 открытых) из-за размера сообщества и active-разработки; типичные темы
схожи с перечисленными ниже.

**Авторизация / вход:**
- muffon #55 «Login to content providers systems» — проблемы с авторизацией к
  провайдерам контента (в т.ч. Яндекс). → Нужен надёжный и понятный флоу входа,
  отдельный под каждый источник, с индикатором состояния логина.

**Воспроизведение / источники:**
- muffon #271 «[bug] spotify source isn't working» — падение конкретного источника;
  → у нас вероятны такие же сбои у Яндекса, нужны чёткие экраны ошибок источника.
- muffon #108 «youtube integration» — не хватает интеграции источника; напоминает,
  что плейлисты/поиск должны работать из любого источника в едином интерфейсе.

**Автовоспроизведение / очередь:**
- muffon #201 «Autoplay after restarting not working» — после перезапуска не
  продолжается воспроизведение. → Обязательно **авторезюме** (запоминать трек,
  позицию и очередь между сессиями; это же типовой запрос в spotube/nuclear).

**Desktop/мобильный UX:**
- muffon #157 «Quit does not work, have to force quit on MacOS» — некорректное
  закрытие приложения (зависание). → Правильная обработка lifecycle (unload, save
  состояния, tray-режим).
- muffon #97 «Improving UX/UI for search» — поиск неудобен. → Быстрый, 
  инкрементальный поиск с подсказками и разделением «треки/альбомы/исполнители».
- muffon #142 «Proxy support» — нужен прокси (пользователи за корпоративными
  сетями / сетевыми фильтрами). Полезно предусмотреть настройку сети.

**Экспорт / плейлисты:**
- Отдельный активно используемый инструмент YandexMusicExport — пользователям
  постоянно нужно **экспортировать плейлисты** (в текст/другие сервисы). → Считаем
  обязательным экспорт/резервную копию библиотеки.

**Скорость / буферизация, реклама / подписка:**
- Косвенные тренды: популярность «мод без Плюса» (YandexMusicBetaMod, 747⭐) и
  слоганов «free, no login, no ads» (muffon, spotube) показывают сильный спрос на
  **быстрый запуск, кэширование и отсутствие навязчивой рекламы**. Плавный
  прогресс-бар с состоянием буферизации и предзагрузкой следующего трека — базовая
  необходимость.

## Лучшие приёмы интерфейса (что скопировать)

Проверенные паттерны из spotube / nuclear / muffon:

1. **Мини-плеер (footer) с прогрессом сверху.** Постоянно видимый нижний бар:
   обложка + название + play/next, над всем содержимым — тонкая линия прогресса.
   Сворачиваемость по клику. (spotube, nuclear — стандарт).
2. **Полноэкранный плеер-«bottom-sheet»** с свайпом вверх: крупная обложка,
   закладки «Плейлист / Похожие / Тексты», элементы управления по центру. (spotube).
3. **Панель очереди (Queue drawer).** Выдвижная панель справа/снизу со списком
   следующих треков, drag&drop перестановкой, индикатор «сейчас играет». (nuclear,
   spotube).
4. **Синхронизированные тексты песен (synced lyrics)** и караоке-подсветка — 
   ключевая «фишка», которую любят в spotube.
5. **Карточки-плитки (grid)** для альбомов/плейлистов с hover-превью и 
   play-кнопкой по наведению; ряды «продолжить», «рекомендации».
6. **Пустые состояния (empty states):** для «нет плейлистов», «поиск без
   результата» — иллюстрация + текст + действие (Кнопка CTA). (muffon, spotube).
7. **Экран входа** с выбором источника контента и понятным статусом авторизации,
   обработкой ошибок (см. жалобу #55).
8. **Настройки:** качество потока, кэш/офлайн, авторезюме, интеграция
   Discord/скробблинг (muffon использует discord-rpc), прокси.
9. **Авторезюме после перезапуска** (запомнить трек/позицию/очередь) — явный
   запрос пользователей (muffon #201).
10. **Глобальные хоткеи** и интеграция с системным media-panel (muffon использует
    hotkeys-js; nuclear — глобальные медиа-клавиши). Скробблинг через LastFM.
11. **Темы/локализация:** i18n (muffon — vue-i18n + массовые переводы Crowdin).
12. **Прогресс буферизации + предзагрузка** следующего трека, состояния
    загрузки/ошибки источника (жалоба #271).

## Иконки

Данные из `package.json` лидеров:

| Проект | Иконки | Формат | Совместимость с React+TS+Vite |
|---|---|---|---|
| **nuclear** | **`lucide`** (подтверждено: issue «Update lucide monorepo», пул @tanstack/react-table) | линейные SVG, 1 цвет (`currentColor`) | ✅ — есть пакет `lucide-react` |
| **muffon** | `fomantic-ui` (иконки Semantic UI) + `emoji-picker-element` | растровые шрифты/набор Semantic | ❌ не React-ориентирован |
| **spotube** | Material Icons (Flutter/Compose) | filled-иконки | ❌ не JS-стек |

**Рекомендация для нас (React + TS + Vite):** использовать **`lucide-react`** —
это **выбор nuclear** (эталона нашей стеки) и лучше всего ложится на требования:

- **Единый стиль** — одна линейная иконография (stroke 2px) по всему приложению;
- **Один цвет** — рисуются через `currentColor` (достаточно менять CSS-цвет, удобно
  для тёмной/светлой темы);
- **Совместимость** — официальный React-пакет, tree-shakeable, отлично работает
  с Vite, MIT.

`pnpm add lucide-react`

Альтернативы (если захотим filled-стиль, а не линейный): **Material Symbols**
(`@material-symbols/tabl...)`) — но у них многоцветность/иной принцип раскраски;
либо **@tabler/icons-react** (тоже `currentColor` + stroke, но набор меньше
брендирован). Первичная рекомендация — **lucide-react**.
